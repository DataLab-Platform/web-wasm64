# DataLab Web — experimental WASM64 deployment

Source, dependency locks and browser tests live in [DataLab-Platform/web](https://github.com/DataLab-Platform/web). This repository controls only the demo at `/web-wasm64/`. Do not configure a custom domain, create a CNAME file, publish from a branch, or change the stable `/web/` site.

1. After source review, push the source commit to `DataLab-Platform/web`. Bootstrap this repository with this workflow on `main`; a push does not deploy. Select GitHub Actions as this repository's Pages source and protect the `github-pages` deployment environment.
2. Dispatch from `main` with the full source SHA. **`check`** runs the HDF5 UI tests and outputs both candidate builds without deploying. **`preview`** runs those tests and publishes only the public site with its experimental notice: tested up to 1 GiB of arrays, >4 GiB not verified. Neither mode runs the large allocation. After publishing, verify the default engine, HDF5 round trip, stable link and explicit Pyodide restart.
3. Review the actual dedicated-machine test results for all tiers including the CSVs, the human smoke test, the source diff and the source PR CI. Commit only the reviewed target `report.json` and `approval.json` under `qualification/<source-sha>/`. The approval must contain `source`, `publicTree`, `benchmarkTree`, the SHA-256 of the exact `report.json` bytes (`reportSha256`), and `manualReview: "approved"`. Do not commit private host information or credentials; keep detailed machine diagnostics with the reviewer. No placeholder approval is supplied.
4. For a **`qualified`** promotion both rebuilt trees must match the approved digests. Only the public build is uploaded to Pages; neither the benchmark generator nor its inputs are published. To roll back, repromote a previously tested revision with its original mode; for a first-deployment failure unpublish only this project's site.
